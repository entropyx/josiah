## Summary

Demantiq's neural inference engine learns to estimate Marketing Mix Model parameters **instantly** — no MCMC, no convergence diagnostics, no hours of fitting. It does this in five steps:

### Step 1: Generate synthetic business datasets

The Demantiq simulator (demand kernel) produces thousands of realistic synthetic datasets, each modeling a complete commercial system through a 15-step data-generating process:

```
D(t) = baseline(t) + Σ media_effects(t) + price_effect(t) + distribution_cap(t)
       + competition(t) + macro(t) + interactions(t) + noise(t)
```

Each dataset varies randomly across: 2-20 media channels, 26-260 time periods, optional pricing (elasticity, promotions), distribution (availability, stockouts), competitive dynamics (SOV suppression), macroeconomic variables (regime changes), endogeneity (feedback loops, confounders), and cross-variable interactions (price x media, distribution x media).

Every dataset has **known ground truth** — the exact betas, ROAS, saturation curves, adstock shapes, price elasticities, and channel contributions that generated the data. This is the training signal.

### Step 2: Train a neural density estimator on (data, truth) pairs

We use **SNPE-C** (Sequential Neural Posterior Estimation, variant C; Greenberg et al., ICML 2019) — a form of Simulation-Based Inference (SBI). The network learns to approximate the Bayesian posterior directly.

**Variable definitions:**

| Symbol | What it represents | Concrete example |
|--------|-------------------|-----------------|
| **θ** (theta) | All the demand model parameters we want to recover | Channel betas (e.g. facebook_beta=200), ROAS per channel, contribution fractions |
| **x** | All the observable business data for one dataset | The time series: weekly revenue (y), spend per channel, price, promo flags, distribution %, competitor SOV, macro indicators |
| **p(θ)** | Prior — what we believe about θ before seeing data | "Betas are between 0 and 500, ROAS is between 0 and 1" (uniform distributions) |
| **p(x \| θ)** | Likelihood — probability of observing this data given these parameters | "If facebook_beta=200 and google_beta=400, how likely is it that we'd see this specific revenue pattern?" This is what the simulator computes implicitly. |
| **p(θ \| x)** | Posterior — what we believe about θ after seeing the data | "Given this client's 104 weeks of revenue and spend data, facebook_beta is probably between 150-250" |
| **q_φ(θ \| x)** | Our neural network's approximation of the posterior. φ are the network's learned weights. | The trained NSF + embedding network. Takes in a client dataset, outputs a probability distribution over all parameters. |

The core equation:

```
q_φ(θ | x) ≈ p(θ | x) = p(x | θ) × p(θ) / p(x)
```

In plain English: **"Our neural network learns to predict the probability of any parameter combination θ, given the observable data x."** It approximates Bayes' theorem without ever computing the likelihood p(x|θ) directly — instead, it learns the pattern from thousands of (data, parameters) training pairs generated by the simulator.

The density estimator is a **Neural Spline Flow (NSF)** (Durkan et al., NeurIPS 2019). An NSF transforms a simple distribution (standard normal) into a complex posterior through a chain of learnable transformations:

```
z ~ N(0, I)                           ← start with simple random noise (61-dimensional)
θ = T_5 ∘ T_4 ∘ T_3 ∘ T_2 ∘ T_1(z)  ← pass through 5 spline transforms, each conditioned on embed(x)
```

Each transform T_k reshapes the distribution a little — bending, stretching, compressing — and the composition of all 5 produces the final complex posterior shape. The transforms are conditioned on embed(x), meaning the shape of the posterior **changes depending on the input data**.

The log-probability of any parameter vector θ given data x is:

```
log q_φ(θ | x) = log π_0(T⁻¹(θ; embed(x))) + log |det ∂T⁻¹/∂θ|
```

Where:
- **π_0** = standard normal density (the base distribution we started from)
- **T⁻¹** = inverse of the spline chain (maps θ back to z)
- **embed(x)** = the 128-dim embedding vector computed by our embedding network from the observable data
- **|det ∂T⁻¹/∂θ|** = the Jacobian determinant, which accounts for how the transforms stretch/compress probability mass

During training, we maximize this log-probability on the training data — pushing the network to assign high probability to the true θ that generated each observed x.

**Why NSF over simpler flows?** Each spline transform uses monotone rational-quadratic spline basis functions. These can model heavy tails, sharp modes, and asymmetric distributions — all common in MMM posteriors where channels may be non-identifiable or have multimodal contributions. Unlike affine coupling layers (RealNVP), splines have universal approximation guarantees on bounded domains.

**Why SNPE-C over alternatives?**
- vs. MCMC (PyMC): Amortized — train once, infer in milliseconds on any new dataset. No convergence diagnostics, no chain mixing issues, no hours of sampling.
- vs. NLE (Neural Likelihood Estimation): NPE gives posteriors in a single forward pass. NLE learns the likelihood p(x|θ) and then still needs MCMC at inference time to get the posterior — defeating the speed advantage.
- vs. NRE (Neural Ratio Estimation): NPE produces the full posterior density, not just likelihood-to-evidence ratios. Easier to sample from and summarize into credible intervals.

### Step 3: Encode the full commercial system

Raw marketing data is high-dimensional and variable-length. The **embedding network** compresses it into a fixed-size conditioning vector for the NSF. It uses four specialized neural network branches, chosen for the specific structure of marketing data:

**Branch 1 — Channel temporal encoder** (Dilated 1D CNN, shared weights across channels)

Each channel's spend time series (26-260 timesteps) is encoded independently by a shared 3-layer dilated CNN:

```
spend_i(T) → Conv1d(1→32, k=7, d=1) → ReLU
           → Conv1d(32→64, k=5, d=2) → ReLU
           → Conv1d(64→64, k=3, d=4) → ReLU
           → AdaptiveAvgPool1d(1) → (64,)
```

**Why dilated CNN?** Dilations of (1, 2, 4) give a receptive field that expands exponentially — 3 layers cover ~30 timesteps, capturing weekly/monthly media patterns. This is O(T) computation vs O(T²) for Transformers, which is overkill for T < 300. Dilated CNNs are the standard temporal encoder in the SBI literature (Radev et al., BayesFlow).

Each channel's temporal embedding is concatenated with a **learnable channel-type embedding** (16 dims, one per channel name: facebook, google, tiktok, ...) giving (80,) per channel. This tells the network "this is Facebook-type media" even across different business configurations.

**Branch 2 — Cross-channel Set Transformer** (Lee et al., ICML 2019)

The set of per-channel embeddings {(80,) × N_channels} is processed by a Set Transformer:

```
{ch_1(80), ch_2(80), ..., ch_N(80)}
  → 2× MultiheadSelfAttention(4 heads, d=80)    [learns cross-channel interactions]
  → Pooling by Multihead Attention (PMA, k=1)     [aggregates to fixed size]
  → set_summary (80,)
```

**Why Set Transformer over DeepSets?** Channels interact — Facebook and Google compete for the same budget, TV amplifies Search, Display may cannibalize Social. DeepSets processes elements independently before aggregation, so it **cannot learn pairwise interactions**. Set Transformer uses attention over set elements, explicitly modeling which channels interact. At 3-20 channels, the O(N²) cost is negligible.

**Why Set Transformer over flattening?** The number of channels varies (3-20). Flattening requires a fixed input size and destroys permutation invariance — reordering channels shouldn't change the answer.

**Branch 3 — Outcome encoder** (Dilated 1D CNN)

The outcome time series y(T) is encoded by an identical dilated CNN architecture → (64,). This captures the temporal pattern of demand — seasonality, trend, level — which constrains what parameter combinations are plausible.

**Branch 4 — Business context encoder** (Dilated 1D CNN, 10 input channels)

All non-media business variables are packed into a fixed-width multivariate time series (T × 10):

| Column | Variable | What it captures |
|--------|----------|-----------------|
| 0 | price | Base product price over time |
| 1 | is_promo | Binary: is a promotion active? |
| 2 | promo_depth | Discount depth (0-35%) |
| 3 | distribution | Weighted distribution % (availability) |
| 4 | stockout | Binary: product unavailable? |
| 5 | competitor_sov | Competitor share of voice |
| 6-9 | macro_1...macro_4 | Consumer confidence, unemployment, etc. |

Missing variables are zero-filled. The CNN encodes this multivariate context → (64,).

**Why encode context separately from media?** Media and business context have fundamentally different structures. Media channels are a variable-size set with permutation invariance. Business context is a fixed set of named variables. Separate encoders let each branch specialize, then the global MLP learns how they interact.

**Global summary assembly:**

```
concat(set_summary(80), y_emb(64), ctx_emb(64), n_channels_normalized(1))
  → MLP(209 → 128 → 128) → ReLU
  → global_summary (128,)
```

This 128-dim vector is the **sufficient statistic** that conditions the NSF. It compresses all observable information — media patterns, demand shape, pricing dynamics, competitive pressure — into a representation optimized for parameter inference.

### Step 4: Infer on new data

Given a new dataset (real client data or a held-out synthetic scenario):

1. Pack the observation: y, spend matrix, business context, channel metadata
2. Forward pass through the embedding network → 128-dim conditioning vector
3. Sample from the NSF: draw z ~ N(0, I), transform through the spline flow conditioned on the embedding
4. Denormalize: convert from [0,1] normalized space back to original parameter scales

The result is **5,000-10,000 posterior samples** per parameter, produced in < 1 second. From these samples we compute:

- **Point estimates**: posterior mean per parameter
- **Uncertainty**: standard deviation, 5th/95th percentiles (90% credible interval)
- **Per-channel**: beta (effect coefficient), ROAS (return on ad spend), contribution fraction
- **Global**: total media contribution as percentage of demand

**Why posterior samples instead of point estimates?** Samples preserve the full joint distribution — correlations between parameters, multimodality, asymmetric uncertainty. A point estimate with an error bar loses this structure. With samples, you can answer questions like "what is the probability that Facebook ROAS > Google ROAS?" directly.

### Step 5: Validate against known truth

Because synthetic datasets have known ground truth, we can rigorously measure posterior quality. This is impossible with real data (you never know the true ROAS).

**Parameter recovery** — Per-parameter MAPE (Mean Absolute Percentage Error) between posterior mean and true value. Computed for betas, ROAS, and contribution fractions across all channels.

**Simulation-Based Calibration (SBC)** (Talts et al., 2018) — The gold standard for checking: "when the engine says it's 90% confident, is it actually right 90% of the time?"

For each test case:
1. Pick true parameters θ_true (e.g., facebook_beta=200, google_beta=400, ...) from the prior
2. Generate synthetic data x using the simulator with those parameters
3. Run the neural engine on x to get 1000 posterior samples θ_post
4. Count how many posterior samples are less than the true value: rank = #{θ_post < θ_true}

Repeat this 500+ times. If the engine is well-calibrated, the ranks form a **uniform histogram** — meaning the true value is equally likely to fall anywhere within the posterior. Deviations reveal problems:
- **U-shaped histogram** → the engine is overconfident (credible intervals too narrow, true value falls in the tails too often)
- **Inverted-U** → the engine is underconfident (credible intervals too wide, wasting precision)
- **Skewed left/right** → systematic bias (engine consistently over/under-estimates)

**Coverage analysis** — A more intuitive check. For each credible level α:

```
empirical_coverage(90%) = "out of 500 test cases, in what fraction
                           does the true beta fall inside the 90% credible interval?"
```

A well-calibrated engine: empirical coverage ≈ nominal level. If the 90% CI contains truth only 60% of the time, the engine is dangerously overconfident — it's more uncertain than it thinks.

**Channel ranking** — Kendall's tau rank correlation between true and inferred channel contribution ordering. Even if absolute values are off, correct ranking is valuable for budget allocation decisions.

The engine is evaluated across **15 benchmark scenarios** with increasing difficulty:
- **clean_room**: 5 channels, no confounding, low noise — any decent model should ace this
- **real_world**: 8 channels, moderate endogeneity, macro effects — practical conditions
- **adversarial**: 12 channels, high endogeneity, low SNR, structural breaks — stress test
- **pricing_dominant**: Most variation from pricing, not media — can it avoid over-attributing to media?
- **many_channels**: 15+ channels with collinearity — decomposition under dimensionality pressure
- And 10 more covering interactions, short data, regime shifts, competition, etc.

### Why this matters

Traditional MMM (PyMC, Robyn, Meridian) takes hours per dataset, requires tractable likelihoods, and can't model arbitrary complexity. Demantiq's neural engine:

- **Trains once** on synthetic data, then infers on any new dataset in milliseconds
- **Models the full commercial system** — not just media, but pricing, distribution, competition, and macro
- **Quantifies uncertainty** — full posterior distributions, not point estimates
- **Scales with complexity** — the simulator can be arbitrarily complex (endogeneity, interactions, regime changes) without making inference harder
- **Validates rigorously** — SBC and coverage analysis on synthetic ground truth, impossible with real data alone

## 1. What Is This?

The Demantiq neural inference engine replaces traditional MCMC-based Marketing Mix Model fitting with **instant, amortized inference**. Instead of running PyMC for hours per client, we train a neural network once on millions of synthetic datasets where ground truth is known, then deploy it to produce posterior distributions over all demand parameters in milliseconds.

This is called **Simulation-Based Inference (SBI)**. No one has applied it to MMM before.

### The Core Idea

Traditional MMM fitting:
```
Client data → Write likelihood → Run MCMC (hours) → Posterior samples
```

Demantiq neural engine:
```
Phase 1 (offline, once):
  Simulator → 200K synthetic datasets with known truth
  Train neural network: (observable data) → posterior distribution

Phase 2 (online, per client):
  Client data → Forward pass through trained network (milliseconds) → Posterior samples
```

## 2. Mathematical Foundation

### 2.1 The Inference Problem

Given observable marketing data **x** = (y, spend₁, ..., spendₖ), we want the posterior distribution over model parameters **θ**:

$$
p(\theta \mid x) = \frac{p(x \mid \theta) \, p(\theta)}{p(x)}
$$

In classical Bayesian MMM, you specify p(x|θ) analytically (e.g., PyMC likelihood) and run MCMC. This is slow and requires tractable likelihoods.

### 2.2 Simulation-Based Inference

SBI sidesteps the likelihood entirely:

1. **Sample** θ⁽ⁱ⁾ ~ p(θ) from the prior
2. **Simulate** x⁽ⁱ⁾ = Simulator(θ⁽ⁱ⁾) using the Demantiq demand kernel
3. **Train** a neural density estimator qφ(θ|x) on the pairs {(x⁽ⁱ⁾, θ⁽ⁱ⁾)}
4. **Infer** on new data: draw samples from qφ(θ|x_observed)

The trained network **amortizes** inference — it works for any observation x, not just the one you trained on. This is the key advantage: train once, deploy everywhere.

### 2.3 Neural Posterior Estimation (SNPE-C)

We use SNPE-C (Sequential Neural Posterior Estimation, variant C) from Greenberg et al. (2019). The density estimator is a **conditional normalizing flow** — specifically a Neural Spline Flow (NSF):

$$
q_\phi(\theta \mid x) = \pi_0(T^{-1}_\phi(\theta; \text{embed}(x))) \cdot \left|\det \frac{\partial T^{-1}_\phi}{\partial \theta}\right|
$$

Where:
- π₀ is a base distribution (standard normal)
- T_φ is an invertible transformation parameterized by neural spline basis functions
- embed(x) is our custom embedding network that compresses the observation into a fixed-size vector
- The flow is autoregressive: each parameter dimension is conditioned on all previous ones

**Why Neural Spline Flows?** They are the most expressive coupling-based normalizing flow architecture. The spline basis allows exact likelihood computation and can model complex, multimodal posterior distributions — important because MMM posteriors are often multimodal when channels are correlated.

### 2.4 Why Not MCMC?

| | MCMC (PyMC) | SBI (Demantiq) |
|---|---|---|
| Inference time | Hours per dataset | Milliseconds per dataset |
| Likelihood | Must be analytical | Simulator is the likelihood |
| DGP complexity | Limited by tractability | Arbitrary (15-step kernel) |
| Amortization | None (re-run for each client) | Train once, use everywhere |
| Endogeneity | Must model explicitly | Simulator generates it |
| Convergence | Diagnostics required | SBC validates once |

#### Why Dilated 1D CNN for Temporal Encoding?

Marketing time series are 26-260 timesteps long. At this scale:
- **Transformers** are overkill — O(T²) attention with no benefit at T<300
- **RNNs/LSTMs** are sequential, hard to parallelize
- **Dilated CNNs** give exponentially expanding receptive fields with O(T) computation

With dilations of (1, 2, 4), three conv layers cover a receptive field of ~30 timesteps, which captures weekly/monthly patterns. AdaptiveAvgPool collapses the remaining temporal dimension.

#### Why Set Transformer for Cross-Channel Attention?

Channels in an MMM are a **set** — their order doesn't matter, but their interactions do (budget competition, audience overlap, synergies). This rules out:
- **Flattening**: Destroys permutation invariance, doesn't generalize to different channel counts
- **DeepSets**: Processes elements independently before aggregation — cannot learn pairwise interactions
- **Set Transformer**: Multi-head self-attention learns which channels interact, then PMA pools into a fixed summary

At 3-20 channels, the O(n²) cost of attention is negligible (~400 operations).

#### Channel-Type Embeddings

Each of the 20 known channel types (facebook, google, tiktok, ...) gets a learnable 16-dim embedding vector. This tells the network "this channel is Facebook-type" even if it hasn't seen this specific combination of channels before. The embedding captures functional properties (upper-funnel vs lower-funnel, broad vs targeted) from data.

### 3.3 Density Estimator (Neural Spline Flow)

The NSF takes the 128-dim embedding from the embedding network and produces a probability distribution over the 61-dim parameter space:

```
global_summary (128,) → NSF conditioning context
                         │
                         ▼
              ┌─────────────────────┐
              │  5 Autoregressive   │
              │  Spline Transforms  │
              │  (128 hidden each)  │
              │                     │
              │  z ~ N(0, I)        │
              │  θ = T(z; context)  │
              └─────────┬───────────┘
                        │
                        ▼
              q(θ | x) — 61-dim posterior
```

Each spline transform is parameterized by a neural network that takes the conditioning context (embedding) and produces knot positions and derivatives for a monotone rational-quadratic spline. This is more expressive than affine coupling layers (used in RealNVP) while maintaining exact log-likelihood computation.

## 4. Training Pipeline

### 4.1 Data Generation

The `TrainingPipeline` generates synthetic training data in streaming batches:

```python
sampler = ScenarioSampler(seed=42)  # Random config generator
pipeline = TrainingPipeline(sampler, output_dir="training_data", batch_size=100)
pipeline.generate(n_total=200000, n_workers=4)
```

Each simulation:
1. `ScenarioSampler` draws random parameters: 2-15 channels, 26-260 periods, optional pricing/endogeneity/competition
2. `demand_kernel.simulate()` runs the 15-step DGP
3. Results converted to fixed-length vectors via `config_to_vector()` and `summary_to_ext_vector()`
4. Saved as compressed `.npz` batches with JSON metadata sidecars

**Resumability**: The pipeline checks for completed batches on disk and skips them, enabling restart after interruption.

### 4.2 Training Loop

```python
engine = DemantiqInferenceEngine(TrainingConfig(n_epochs=200))
engine.train(data_dir="training_data", save_dir="trained_model")
```

Internally:
1. Load all `.npz` batches into `DemantiqDataset`
2. Split 90/10 train/validation
3. For each sample: pack (y, spend, metadata) into flat observation tensor
4. Extract reduced 61-dim theta from extended truth vector, normalize
5. Build SNPE_C with NSF density estimator + custom embedding network
6. Train with early stopping (patience=20 epochs)
7. Build posterior from trained density estimator
8. Evaluate on validation set (MAPE metric)

### 4.3 Observation Packing

sbi expects a single flat tensor per observation. We pack our multi-part data as:

```
[y₁...y_T, spend₁₁...spend_TK, n_channels, n_periods, type_id₁...type_idK]
  \_max_T_/  \___max_T × max_ch___/    \1/      \1/     \___max_ch___/
```

The `DemantiqEmbeddingWrapper` unpacks this and routes to the appropriate encoder components. Integer metadata (n_channels, type_ids) is recovered via `.round().long().clamp()` to handle any z-scoring that sbi applies internally.

## 6. Diagnostics

### 6.1 Simulation-Based Calibration (SBC)

SBC answers: "Is the posterior well-calibrated?" If you sample θ_true from the prior, simulate x, and draw posterior samples, the rank of θ_true among the posterior samples should be uniformly distributed.

**Protocol**:
1. For i = 1, ..., N:
   - Draw θ_true⁽ⁱ⁾ ~ prior
   - Simulate x⁽ⁱ⁾ = Simulator(θ_true⁽ⁱ⁾)
   - Draw θ_post⁽¹⁾,...,θ_post⁽L⁾ ~ posterior(·|x⁽ⁱ⁾)
   - rank_d = #{j : θ_post⁽ʲ⁾_d < θ_true⁽ⁱ⁾_d}
2. Histogram of ranks should be uniform
3. KS test p-value against Uniform(0, L)

**Interpretation**:
- Uniform histograms → posterior is calibrated
- U-shaped → posterior is overconfident (too narrow)
- Inverted-U → posterior is underconfident (too wide)
- Skewed → posterior is biased

### 6.2 Coverage Analysis

For nominal levels α ∈ {50%, 80%, 90%, 95%}:
- Compute the α credible interval from posterior samples
- Check if θ_true falls within the interval
- Empirical coverage should match nominal level

**Expected**: 90% of true values inside 90% CI. Deviations indicate miscalibration.

### 6.3 Posterior Predictive Checks

Sample parameters from the posterior, feed them back to the simulator, and check whether the simulated data resembles the original observation. This validates the full loop: embedding → posterior → simulation.

## 8. Phase Roadmap

### Phase 1 (Current): Monolithic SNPE

- Single posterior over 61-dim reduced space
- SNPE_C + NSF density estimator
- Custom embedding network (DilatedConv1D + Set Transformer)
- Infers: betas, ROAS, contribution fractions per channel

### Phase 2 (Next): Compositional Inference

- Factored posterior: global component + per-channel components
- Each channel's parameters (beta, saturation curve, adstock shape) inferred by a shared per-channel network conditioned on cross-channel context from the Set Transformer
- Dramatically reduces effective dimensionality: ~10 params per component instead of 200+
- Scales naturally: add a channel = add a component, no retraining

### Phase 3: Calibration Interface

- Inject experimental evidence (geo-lift, brand lift, price tests) as informative priors
- Importance weighting on NPE posterior samples, or score-based prior injection
- Evidence database with similarity-weighted retrieval across clients

### Phase 4: Production

- Streamlit inference page
- Head-to-head benchmarking vs PyMC Marketing and Meridian
- Model serialization and inference API
