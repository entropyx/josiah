# How Demantiq's Neural Engine Works

## The Problem We're Solving

A business makes money from many things at once:
- **Media ads** (Facebook, Google, TikTok, etc.)
- **Price changes** (discounts, promotions)
- **Distribution** (how many stores carry the product)
- **Competition** (what competitors are doing)
- **The economy** (consumer confidence, recession, etc.)
- **Organic demand** (people who would buy anyway)

The question every business asks: **"How much did each of these things contribute to my sales?"**

This is hard because everything happens at the same time. When sales go up during Black Friday, was it the Facebook ad? The 30% discount? The fact that competitors were also running sales? All three?

Traditional approaches (PyMC, Robyn, Meridian) take **hours per dataset** using a method called MCMC — basically trying millions of random parameter combinations to see which ones explain the data. Our approach: **teach a neural network to answer this question instantly** by showing it thousands of practice problems where we already know the answer.

---

## The Analogy: Teaching a Doctor

Imagine training a doctor to diagnose patients:

**Traditional approach (MCMC):**
> Every time a patient walks in, the doctor runs every possible test, checks every possible disease, and slowly narrows down the diagnosis over hours.

**Our approach (SBI):**
> Before seeing real patients, the doctor studies **10,000 case files** where the diagnosis is already known. After enough practice, the doctor can look at a new patient's symptoms and instantly say: "This looks like case #4,372 — 80% chance it's condition X, 15% chance condition Y."

The case files are our **synthetic datasets** (generated by the Demantiq simulator). The doctor is our **neural network**. The diagnosis is the **posterior distribution** over business parameters.

## Step by Step: What Happens

### Step 1: Build a Fake Business Simulator

We built a math model that creates realistic fake business data. Think of it like SimCity for marketing:

```
                    THE SIMULATOR
                    ════════════

    Inputs (the "truth" we choose):         Output (what we'd observe):
    ┌─────────────────────────┐             ┌──────────────────────┐
    │ facebook_beta = 150     │             │ Week 1: sales = 1,243│
    │ google_beta = 200       │             │ Week 2: sales = 1,387│
    │ price_elasticity = -1.5 │  ───────►   │ Week 3: sales = 1,102│
    │ organic_demand = 1000   │             │ ...                  │
    │ noise = 20              │             │ Week 104: sales =1,455│
    └─────────────────────────┘             └──────────────────────┘

    We KNOW the truth                       We SEE the sales data
    (because we chose it)                   (plus spend, prices, etc.)
```

The simulator follows the demand equation:

```
sales(t) = organic_demand
         + facebook_beta × effect(facebook_spend(t))
         + google_beta × effect(google_spend(t))
         + price_elasticity × ln(price(t) / base_price)
         + distribution_effect(t)
         + competition_effect(t)
         + noise(t)
```

Where `effect()` applies two transforms:
- **Adstock**: Today's ad has a lingering effect tomorrow (like a memory decay)
- **Saturation**: Spending $1M on Facebook doesn't help 10x more than $100K (diminishing returns)

### Step 2: Generate Thousands of Practice Problems

We run the simulator 5,000-50,000 times, each with **different random parameters**:

```
    Dataset #1:                  Dataset #2:                  Dataset #5000:
    ┌────────────────┐           ┌────────────────┐           ┌────────────────┐
    │ Truth:         │           │ Truth:         │           │ Truth:         │
    │  fb_beta=150   │           │  fb_beta=320   │           │  fb_beta=45    │
    │  gg_beta=200   │           │  gg_beta=80    │           │  gg_beta=410   │
    │  elasticity=-1 │           │  elasticity=-3 │           │  elasticity=-0.5│
    │                │           │                │           │                │
    │ Data:          │           │ Data:          │           │ Data:          │
    │  104 weeks of  │           │  104 weeks of  │           │  104 weeks of  │
    │  sales, spend, │           │  sales, spend, │           │  sales, spend, │
    │  prices, etc.  │           │  prices, etc.  │           │  prices, etc.  │
    └────────────────┘           └────────────────┘           └────────────────┘

    Each dataset is a "practice problem" where we know the answer.
```

### Step 3: Teach the Neural Network

The neural network has two parts:

```
    PART 1: THE PATTERN READER (Embedding Network)
    ═══════════════════════════════════════════════

    Takes messy real-world data and extracts the important patterns:

    ┌─────────────────────────────────────────────────────────────────┐
    │                                                                 │
    │  Sales time series ──► [Dilated CNN] ──► "sales pattern" (64 numbers)
    │                                                                 │
    │  Spend per channel ──► [Dilated CNN] ──► "spend pattern" per channel
    │        │                                       │                │
    │        ▼                                       ▼                │
    │  [Channel labels] ──► [Set Transformer] ──► "how channels      │
    │   (fb, google...)      (learns which         interact" (80)     │
    │                         channels interact)                      │
    │                                                                 │
    │  Price, promos,  ──► [Dilated CNN] ──► "business context" (64) │
    │  distribution,                                                  │
    │  competition                                                    │
    │                                                                 │
    │  All combined ──► [MLP] ──► SUMMARY VECTOR (128-256 numbers)   │
    │                                                                 │
    └─────────────────────────────────────────────────────────────────┘

    This summary vector captures EVERYTHING important about the
    business data in a compact form. Think of it like a blood test
    result — a few numbers that summarize a complex system.


    PART 2: THE ANSWER GENERATOR (Neural Spline Flow)
    ══════════════════════════════════════════════════

    Takes the summary and produces a PROBABILITY DISTRIBUTION
    over all possible parameter values:

    ┌─────────────────────────────────────────────────────────────────┐
    │                                                                 │
    │  Summary vector ──► [Spline Transform 1]                       │
    │                      ──► [Spline Transform 2]                  │
    │                      ──► [Spline Transform 3]                  │
    │                      ──► [Spline Transform 4]                  │
    │                      ──► [Spline Transform 5]                  │
    │                                                                 │
    │  Output: NOT a single answer, but a DISTRIBUTION               │
    │                                                                 │
    │  "facebook_beta is probably 120-180,                            │
    │   with most likely value around 150"                            │
    │                                                                 │
    │  "price_elasticity is probably -1.2 to -1.8,                   │
    │   with most likely value around -1.5"                           │
    │                                                                 │
    └─────────────────────────────────────────────────────────────────┘
```

**Why a distribution instead of a single number?**

Because with real data, there's always uncertainty. If Facebook and Google spend always go up together, it's hard to tell which one actually drove sales. The distribution honestly shows this: "I think Facebook beta is 120-180, but I'm not sure if it's 130 or 170."

A single number like "Facebook beta = 150" hides this uncertainty. A distribution reveals it.

### Step 4: The Training Process

```
    FOR EACH of the 5,000 practice datasets:
    ═════════════════════════════════════════

    1. Feed the DATA (sales, spend, prices) to the Pattern Reader
       ──► Get a summary vector

    2. Feed the summary to the Answer Generator
       ──► Get a predicted distribution over parameters

    3. Check: does the predicted distribution put high probability
       on the TRUE parameters that generated this dataset?

    4. If not: adjust the neural network's weights to make it
       more likely to predict correctly next time

    Repeat for 50-200 passes through all 5,000 datasets.

    ┌─────────────────────────────────────────────────────┐
    │                                                     │
    │  Training Loss:                                     │
    │                                                     │
    │  "How surprised would the network be if the         │
    │   true parameters were the answer?"                 │
    │                                                     │
    │  Low surprise = good prediction = low loss          │
    │  High surprise = bad prediction = high loss         │
    │                                                     │
    │  The network minimizes this surprise over           │
    │  thousands of practice problems.                    │
    │                                                     │
    └─────────────────────────────────────────────────────┘
```

The math behind training:

```
    loss = -log q(θ_true | data)

    In English: "The negative log of the probability the network
    assigns to the true parameters, given the data."

    We want this to be as LOW as possible.
    Low loss = network assigns HIGH probability to the truth.
```

## Why Each Piece Exists

### Why a simulator? (Can't we just use real data?)

Real data has no ground truth. If you fit a model to Coca-Cola's sales data, you'll never know if "Facebook beta = 200" is correct — nobody knows the true answer. With a simulator, we CHOOSE the truth, so we can measure if our neural network gets it right.

### Why Dilated CNNs? (For reading time series)

Marketing data has patterns at multiple scales: daily noise, weekly cycles, monthly trends, seasonal patterns. Dilated convolutions read patterns at each scale simultaneously:

```
    Dilation = 1:  reads day-to-day changes     ●─●─●─●─●─●─●
    Dilation = 2:  reads week-to-week patterns   ●───●───●───●
    Dilation = 4:  reads month-to-month trends   ●───────●───────●

    Three layers cover all timescales with minimal computation.
```

### Why Set Transformer? (For reading channels)

Channels are a SET — their order doesn't matter (listing "Facebook, Google" is the same as "Google, Facebook"), but their INTERACTIONS do matter (if Facebook and Google target the same audience, they compete for attention).

Set Transformer uses **attention** to learn which channels interact:

```
    "Facebook spend is high AND Google spend is high"
     → attention learns: these compete (audience overlap)
     → reduces each channel's estimated individual effect

    "TV spend is high AND Search spend is high"
     → attention learns: these synergize (TV drives search)
     → increases the combined estimated effect
```

### Why Neural Spline Flows? (For the answer)

We need to output a **probability distribution**, not a number. Neural Spline Flows are the best tool because:

1. They can model complex shapes (asymmetric, multimodal, heavy-tailed)
2. They give exact probabilities (not approximations)
3. They're fast to sample from (important for generating 10,000 posterior samples)

How they work:

```
    Start with simple noise:     z ~ Normal(0, 1)
                                    │
                                    ▼
    Apply 5 learned transforms:  z ──► T1 ──► T2 ──► T3 ──► T4 ──► T5 ──► θ
                                    │
    Each transform is a           Bend, stretch, compress
    flexible spline curve:        the distribution to match
                                  what the data says
                                    │
                                    ▼
    End with complex posterior:  θ ~ q(θ | data)

    The transforms are CONDITIONED on the data summary,
    so different data produces different posterior shapes.
```

### Why summary statistics? (The simple embedding option)

Instead of feeding raw time series (thousands of numbers) to the network, we can pre-compute meaningful summaries:

```
    Raw data (5,200 numbers):          Summary (63 numbers):
    ┌──────────────────────┐           ┌────────────────────────────┐
    │ y[1], y[2], ... y[104]│          │ y_mean, y_std, y_trend     │
    │ fb_spend[1..104]      │   ──►    │ fb_mean, fb_std, fb_corr_y │
    │ gg_spend[1..104]      │          │ gg_mean, gg_std, gg_corr_y │
    │ price[1..104]         │          │ price_mean, price_corr_y   │
    │ distribution[1..104]  │          │ dist_mean, dist_corr_y     │
    │ ...                   │          │ ...                        │
    └──────────────────────┘           └────────────────────────────┘

    63 numbers is MUCH easier for the NSF to learn from than 5,200.
    Trade-off: loses temporal structure (when things happened).
```

## How We Check If It Works

### Simulation-Based Calibration (SBC)

The key question: **"When the network says it's 90% confident, is it actually right 90% of the time?"**

```
    Test procedure:
    ═══════════════

    Repeat 500 times:
      1. Pick random true parameters (e.g., fb_beta = 200)
      2. Simulate fake data using those parameters
      3. Ask the neural network: "What do you think fb_beta is?"
      4. Network says: "90% CI is [150, 250]"
      5. Check: is the true value (200) inside [150, 250]? YES ✓

    Count: out of 500 tests, how many times was the truth
    inside the 90% CI?

    If answer ≈ 450 (90%): CALIBRATED ✓ (honest uncertainty)
    If answer ≈ 300 (60%): OVERCONFIDENT ✗ (CIs too narrow)
    If answer ≈ 490 (98%): UNDERCONFIDENT (CIs too wide, wasting precision)
```

We compare against:
- **OLS** (simple linear regression) — the dumbest baseline
- **PyMC Marketing** — the current Bayesian gold standard
- **Known truth** — because we have the simulator

```

    ├──────────────┼────────────┼────────────┼────────────┤
```

## What's Working and What's Not (Honest Status)

### Working:
- The architecture trains and produces posteriors
- Beats OLS baseline on every channel
- Total media contribution is in the right ballpark
- ROAS estimates are reasonable (10-30% error)
- Inference is instant (< 1 second)

### Not working yet:
- Betas are biased high (~50% error) — the network overestimates media's effect
- Price elasticity is barely detected — the network hasn't learned to separate pricing from media
- Credible intervals are too wide — the network is uncertain about everything

### Why:
- Not enough training data diversity for the full commercial system
- The current embedding network may be too complex for the amount of data we have
- 17-62 dimensional posterior is at the edge of what NSFs handle with 5K samples

### Path forward:
1. **Simple embedding** (summary statistics) to test if the architecture works with less data
2. **50K training samples** with the full embedding if simple works
3. **Compositional inference** — instead of one big 62-dim posterior, break it into per-channel posteriors of ~5 dims each
